# Deploying FarmSight (task C10)

Two free services: the **API on Render** (`render.yaml`) and the **web app on Vercel** (`frontend/vercel.json`).
About 15 minutes the first time. Do it before Saturday night, then test the link on a phone over mobile data.

## 1. API on Render

1. Sign in at https://render.com with GitHub, then **New → Blueprint** and pick
   `Muhammad-Abdullah24/AICON-Claude-s-Plan`. Render reads `render.yaml` and creates `farmsight-api`.
2. It asks for the values marked `sync: false`. Fill in what you have; you can add the rest later under
   **Environment** (each change redeploys):
   - `FS_CORS_ORIGINS`: leave as `http://localhost:5173` for now; set it to the Vercel URL after step 2.
   - `FS_LLM_API_KEY`: the Gemini key (Hamza shares it outside git). Without it, chat uses its template answer.
   - `FS_WA_*`: from the Meta app (task A3). Without them, the WhatsApp webhook refuses requests (by design).
   - `FS_JWT_SECRET` and `FS_ADMIN_TOKEN` are generated by Render. Copy `FS_ADMIN_TOKEN` somewhere safe: the alert
     trigger needs it (`docs/DEMO.md` section 3).
3. The first build takes a few minutes (it installs XGBoost). When it is live, open
   `https://farmsight-api.onrender.com/health` (your URL may differ): it must say `{"status":"ok"}`. Then
   `/api/advice?crop=wheat&mandi=bahawalpur` must show real AMIS prices.

Free-plan limits to plan around:
- The service **sleeps after 15 idle minutes** and the first request after that takes up to a minute. Open `/health`
  on the demo morning and again at 11:15, just before our 11:27 slot.
- The disk is not kept: **SQLite starts empty on every deploy or restart**, then the demo farmer (+920000000001) is
  seeded again. Farmers registered on the deployed site disappear on restart. That is fine for the demo; say so if
  asked.

## 2. Web app on Vercel

1. Sign in at https://vercel.com with GitHub, **Add New → Project**, import the same repository.
2. **Root Directory: `frontend`** (important). Vercel then finds `vercel.json` (build `npm run build`, output `dist`,
   every path served by `index.html` so `/why` and `/?as_of=…` work on reload).
3. **Environment Variables:** `VITE_API_BASE_URL` = the Render URL, with no trailing slash, e.g.
   `https://farmsight-api.onrender.com`. It is baked in at build time, so redeploy after changing it.
4. Deploy, and copy the URL (e.g. `https://farmsight.vercel.app`).

> **Since 10 Oct, `vercel.json` forwards `/api/*` and `/health` to the Render API** (`farmsight-api-auat`). The
> site works even if `VITE_API_BASE_URL` is missing from a build, and those requests need no CORS. If the Render
> address changes, update both `vercel.json` files. The first request after Render's idle sleep can take about a minute.

## 3. Connect them

1. In Render, set `FS_CORS_ORIGINS` to the Vercel URL (no trailing slash). For several, separate with commas, e.g.
   `https://farmsight.vercel.app,http://localhost:5173`.
2. Open the Vercel URL on a phone over mobile data: Home must show the wheat card, "prices as of …" and the weather
   line. Log in on Profile with `+920000000001`.
3. WhatsApp (after A3): in the Meta app, **WhatsApp → Configuration → Webhook**: callback URL
   `https://<render URL>/webhooks/whatsapp`, verify token = `FS_WA_VERIFY_TOKEN`, subscribe to `messages`.

## 4. If something is wrong

| Symptom | Fix |
|---|---|
| Web app says "Could not reach the server" | `VITE_API_BASE_URL` missing or wrong (redeploy Vercel after fixing), or the API is asleep (open `/health` and wait) |
| Browser console shows a CORS error | `FS_CORS_ORIGINS` on Render does not exactly match the Vercel URL (scheme, no trailing slash) |
| `/why` gives 404 on reload | Vercel's Root Directory is not `frontend`, so `vercel.json` was not used |
| Chat always says "template" | `FS_LLM_API_KEY` is not set on Render, or Gemini's free tier is rate-limiting |
| Render rejects `PYTHON_VERSION` "3.11" | Set it to a full version, e.g. `3.11.13`, under Environment |
| Render build runs out of memory or time | Retry once; XGBoost is the large install. Without it, the API still runs (the wheat direction call switches off) |

Keep the laptop copy ready as the backup (README "Run locally").
